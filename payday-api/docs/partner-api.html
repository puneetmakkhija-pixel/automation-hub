PaydayOS partner API

The NBFC's loan system as a back end for a partner app. The partner shows the screens. PaydayOS holds the loan record, pays the borrower directly and collects repayments directly. Events we send are listed under webhooks and signed: x-payday-signature is sha256= plus the HMAC-SHA256 of {x-payday-timestamp}.{raw body} with your shared secret.

Send your key as x-api-key. The same document is served at GET /openapi.json. The step-by-step guide is docs/PARTNER_GUIDE.md.

Lender

GET /v1/lender Who the lender is

The NBFC name, registration, address and grievance officer, and the lending service provider (BuddyLoan). Show these in the app and on the website. complete: false means a lender detail is not set yet.

Who may call it: partner, ops, admin.

    "name": "A. Officer",
    "email": "g@example.com",
    "phone": "..."
  },
  "lending_service_provider": {
    "name": "BuddyLoan"
  },
  "complete": true,
  "missing": []

POST /v1/customers/{customer_id}/consents Record the borrower's permission

Record each permission with the text version the borrower saw and the channel. No identity or credit check runs until kyc, credit_bureau and terms are on record.

Who may call it: partner, ops, admin.

Parameters: customer_id (path)

{

    "kyc",
    "credit_bureau",
    "terms"

  "text_version": "v1",
  "channel": "app"
}

{
  "recorded": [
    "kyc",
    "credit_bureau",
    "terms"
  ]
}

Applications

POST /v1/applications Apply: run the checks and get a decision

Runs the identity check, pulls the credit report and decides. A partner key may open at most 3 applications per customer in 24 hours (429 TOO_MANY_APPLICATIONS). Send an Idempotency-Key so a retry never opens a second application.

Who may call it: partner, ops, admin.

Parameters: Idempotency-Key (header)

Request

{
  "customer_id": "c0a8...",
  "product_code": "PAYDAY_30",
  "requested_amount": 10000,
  "intake": {
    "declaredSalary": 40000,
    "tenureMonths": 24,
    "employerCategory": "listed_large",
    "residence": "rented_long",
    "purposeClarity": "generic",
    "referencesVerified": "none"
  },
  "pan": "ABCDE1234F"
}

Loans

GET /v1/loans/{loan_id} The loan: schedule, balance, cooling-off

Call this whenever My Loans opens. Keep no copy of the ledger. cooling_off.open is true during the window and amount_due is what an exit costs today.

Who may call it: partner, ops, admin.

Parameters: loan_id (path)

Response 200

{
  "loan_id": "l9f8...",
  "status": "active",
  "principal": 10000,
  "due_date": "2026-11-15",
  "outstanding": 10800,
  "days_overdue": 0,
  "cooling_off": {
    "open": true,
    "amount_due": 10026.67
  }
}
POST /v1/loans/{loan_id}/collect Create a repayment link

The link pays straight into the lender's account. The money never passes through BuddyLoan. The payment is confirmed to us by the payment vendor, which then sends you payment.received.

Who may call it: partner, ops, admin.

Parameters: loan_id (path), Idempotency-Key (header)

Request

{
  "amount": 10800
}

Response 200

{
  "provider_ref": "pay_123",
  "status": "created",
  "payment_url": "https://...",
  "amount": 10800
}
POST /v1/loans/{loan_id}/cooling-off The borrower asks to exit in the cooling-off window

Returns what to pay: the principal plus the fee for the days held. Pay with a repayment link inside the window. 409 once the window has ended.

Who may call it: partner, ops, admin.

Parameters: loan_id (path)

Response 200

{
  "open": true,
  "ends": "2026-10-17",
  "days_held": 1,
  "principal": 10000,
  "fee": 26.67,
  "fee_reversed": 773.33,
  "amount_due": 10026.67,
  "requested": true
}

Events

GET /v1/events Read your events back

Everything we queued for you, oldest first. Use it to catch up after an outage: pass since (the next_since of your last read) and status.

Who may call it: partner (ops and admin add partner_id).

Response 200

{
  "events": [
    {
      "id": "e1...",
      "event_id": "a1b2...:application.decided",
      "type": "application.decided",
      "status": "delivered",
      "attempts": 1,
      "data": {}
    }
  ],
  "next_since": "2026-10-16T10:00:00Z"
}
