This dashboard has been retired

It was a static mockup, not a monitoring tool.

Why it was removed

Every status it displayed was hardcoded text — “Healthy (99.95% uptime)”, “12/20 active”, and the green “Connected” badges were literal strings in the HTML, not readings from any service.

It reported the same healthy state whatever was actually happening, including during a live outage when the IVR service was returning HTTP 502 to every request. A status page that cannot report a failure is worse than none.

Use this instead

The live console checks the IVR service on every load and reports exactly what came back, including the failure reason and the URL it called:

crmbusinessloans.com/marketing →

Checking the service directly

  • /health — returns ok
  • /console — the service’s own dashboard
  • /voice, /webhooks/* — call routing

Base: https://ivr-voice-bot-system-production.up.railway.app

The pages that stood here polled API endpoints the service never implemented. Restoring a dashboard here means building those endpoints first.
